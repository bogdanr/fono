How the scores are built

Every number below is computed from the same four inputs, so two findings with the same score really are comparable. Nothing is scored by feel.

  • Importance (0–10) = severity base (S1 6, S2 4, S3 2, S4 1) + harm tags (work‑loss 2, crash 2, security 2, wrong‑output 2, silent 1) + reachability (default config 2, needs a setting 1, rare 0), capped at 10.
  • Confidence (0–1) comes from the Stage 3 verification state, not from how convincing the argument reads: 1.00 reproduced by running code, 0.95 proven by a single command, 0.70 high confidence read-only, 0.50 medium, 0.30 low.
  • Cost is XS (under 5 lines), S (one function), M (one module), L (a design decision), weighted 1 / 1.5 / 2.5 / 4.
  • Value = importance × confidence ÷ cost weight. This deliberately ranks a three-line certain fix above a large speculative one, which is what makes the list actionable rather than merely alarming.

The clipboard fallback that should catch it already exists and is correct — it is simply never reached, because the error was converted to Ok(()) one layer down.

Both S1s are pinned to this list.

Four bundles that are cheaper together than apart

Approving these as groups costs less than approving their members, because one change serves all of them.

One shutdown channel

F-B001 + F-B002 + F-C001

Fed by SIGTERM, SIGINT, tray Quit and Request::Shutdown, with run() returning normally. Three S2s close together for the cost of roughly one, two false comments become true, and the installers need no change at all.

Wyoming authentication

F-H001 + F-H002

Must ship together. Fixing the check alone produces a listener that rejects users who configured the token the documented way; fixing the lookup alone changes nothing.

Bound the network surface

F-G001 + F-G002 + F-G003 + F-C003 + F-C005

A Semaphore on both accept loops caps four of these at once. All five are the same question: does the code allocate what the peer claims, or what the peer delivers?

One mutex poisoning policy

F-B005 + F-C002 + F-A003

Four sites, four spellings, no shared policy. The data is Copy scalars that cannot tear, so the last written value beats a default. One decision, not four fixes.

What the audit did not find

Load-bearing for how much weight to put on the rest of the list.

  • No memory-safety defect across 140 unsafe sites. Null checks precede every use, handles close on every path, layout assumptions are asserted rather than assumed.
  • No secret logged anywhere. Every logging macro across all 272 source files containing api_key, secret, password or bearer emits only key names and file paths.
  • No on-disk permission defect. All four SQLite stores chmod the database and its -wal/-shm sidecars to 0600, each with a test that creates the file 0644 and asserts it comes back 0600.
  • No inconsistent error mapping across the sixteen cloud providers — the expected defect in that surface. Classification is centralised; the divergence is one layer below, in transport config.
  • No bounds defect in 2,729 lines of software rasteriser. Every framebuffer write goes through get_mut; negative coordinates are filtered before the cast that would wrap them.
One caution on reading coverage as confidence. F-A006 — batch dictation cannot be cancelled — lives in one of the best-covered files in the workspace. Its tests are thorough and still miss it, because they assert the transitions that exist rather than probing for the one that is absent. Coverage measures what runs, not what is missing.
