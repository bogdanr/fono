# Fix CI on 0.18.0 and republish

State on 2026-08-05: `04e0314` is pushed to `origin/main` and tagged `v0.18.0`.
Both workflows failed on it (CI run 31006101864, release run 31006106011).
Four failures, three of them regressions from the one-ggml change. This plan
fixes the three, republishes 0.18.0, and handles the fourth (Windows)
separately because it does not block the release.

## The four failures and their causes

### F1 — License / advisory audit (trivial)

`deny.toml:110` — `allow-git` names `https://github.com/bogdanr/llama-cpp-rs`,
which no longer exists in `Cargo.lock`. The only git source left is the
whisper fork, and it is not allowed, so cargo-deny denies it. The comment
above the line is stale too (it still describes the GDN carry patch that
upstream 0.1.154 made obsolete).

### F2 — Ubuntu, `fono-bench` equivalence step only (link error)

```
libwhisper.a(whisper.cpp.o): undefined reference to `operator new[](unsigned long)'
                             undefined reference to `std::istream::read(char*, long)'
```

`whisper.cpp` is C++. The link line is
`-Wl,--as-needed -Bdynamic -lstdc++ -lwhisper -lggml -lggml-base -lggml-cpu`:
the single shared `-lstdc++` sits before `-lwhisper`, and our own
`--as-needed` (`.cargo/config.toml`, predates this work) discards it before
`whisper.cpp.o` is pulled.

Why the main `fono` binary survives: `Cargo.toml:123` enables `static-stdcxx`
on `llama-cpp-2`, so llama emits `static=stdc++` plus a search path
(`llama-cpp-sys-2-0.1.154/build.rs:1361-1365`). That is a different directive
from `dylib=stdc++`, so cargo does not dedup it, and as a static lib it is
linked inside the group with the whisper archives where order does not
matter. `fono-bench --features equivalence,whisper-local` has no
`llama-cpp-2` in its graph at all — only `llama-cpp-sys-2` reached ggml-only
through whisper's optional edge — so no rescue reaches it.

### F3 — macOS build & test, and the metal size audit (hard error)

```
ld: library 'ggml-blas' not found
```

The fork emits `ggml-blas` unconditionally on macOS
(`whisper-rs/sys/build.rs:369-375`). Under `system-ggml` the ggml comes from
llama's build, which has no `ggml-blas` target. Also a non-fatal warning:
`search path '.../llama-cpp-sys-2-.../out/lib64' not found` — llama installs
to `lib` on macOS, not `lib64`.

### F4 — Windows heap corruption (NOT release-blocking)

`0xc0000374` in `local_backends_coexist`, now in test 2
(`shared_llama_backend_inits_once` → `LlamaBackend::init()`), with **zero**
duplicate-symbol warnings and one ggml confirmed in effect. The two-copy
diagnosis is dead as the cause of this crash. Non-blocking because the CI
job is `continue-on-error` (`ci.yml:586`) and the release workflow
(`release.yml:253-259`) builds the `.exe` without running tests.

## Work items, in order

### 1. deny.toml (F1)

- `allow-git`: `bogdanr/llama-cpp-rs` → `bogdanr/whisper-rs`.
- Rewrite the comment: the whisper fork carries PR 260 (`system-ggml`) plus
  the `llama-ggml` edge until upstream merges them.
- Verify: `cargo deny check` locally if cargo-deny is installed; otherwise
  this is CI-verified.

### 2. Ubuntu link (F2) — fix in the whisper fork

Candidate A (do first): in `whisper-rs/sys/Cargo.toml`, add
`features = ["static-stdcxx"]` to the optional `llama-cpp-sys-2` dep. Every
`llama-ggml` consumer then gets the same static C++ runtime rescue the main
binary already has. No new risk class — main fono already links this way.

Candidate B (only if A fails): in `whisper-rs/sys/build.rs`, drop the
top-of-script `dylib=stdc++` and emit `static=stdc++` + the compiler's
static-archive search path **after** the whisper/ggml emissions.

Verification (local, mandatory — CI is too slow to iterate):

1. Force a REAL relink, not a cache hit: delete
   `target/release/fono-bench` AND touch a real source file, then
   `cargo build --release -p fono-bench --features equivalence,whisper-local -vv`.
2. In the `-vv` link line, confirm a `stdc++` entry lands where it survives
   (static, or after `-lwhisper`), and the build exits 0.
3. Run the exact CI step command from `ci.yml` for the equivalence gate.

### 3. macOS (F3) — fix in the whisper fork

In `whisper-rs/sys/build.rs`, under `system-ggml`:

- Emit each ggml backend lib (`ggml-blas`, `ggml-hip`, `ggml-metal`,
  `ggml-cuda`) only if the library file actually exists in the provider's
  install dir. Existence check, not target-OS guesswork.
- Probe both `lib` and `lib64` for the link-search path (kills the `lib64`
  warning on macOS).

Local verification: the Linux build must still link (existence checks pass
for `ggml`, `ggml-base`, `ggml-cpu`); macOS itself is CI-verified only.

### 4. Fork push + rev bump

- Push `fono-llama-ggml` on `bogdanr/whisper-rs` (user has already OK'd
  pushes for this work).
- Bump the rev in fono's `[patch.crates-io]`, `cargo update -p whisper-rs-sys`,
  confirm the lock moves and nothing else does.

### 5. Release hygiene

- `CHANGELOG.md` `## [0.18.0]` → `### Fixed`: one entry for the macOS build,
  one for the bench link. User language, no jargon in the subject.
- `docs/status.md`: session entry — what failed, why, what the fix was, and
  the honest note that the Windows diagnosis is still open.

### 6. Gates (all four, niced)

```
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --tests --lib
./tests/check.sh --size-budget
```

### 7. Republish

Same procedure as before: amend the release commit, `git push
--force-with-lease origin main`, move `v0.18.0`, push the tag. The tag push
retriggers the release build.

Expected CI after this: License, ubuntu, macOS, metal audit, size gates
green. Windows still red — known, non-blocking.

### 8. Windows (F4) — after republication, needs a decision

Two options, pick one when we get there:

- (a) Throwaway CI branch with a matrix: `windows-defaults` as-is vs without
  `accel-vulkan`. ~20 min, discriminates the last untested variable (the
  GPU-less runner's Vulkan loader). Requires a push.
- (b) The user's Windows box (192.168.0.132) when reachable: run the CI
  feature set locally.

Do NOT paper over the test to make CI green — it is the only thing telling
us the truth about the shipped Windows binary.

## Out of scope

- Merging PR 260 upstream or unforking whisper-rs.
- The `fono-bench` graph growing `llama-cpp-2` (rejected: builds full
  llama.cpp in the bench for no functional gain; the fork fix is smaller and
  helps every consumer).
